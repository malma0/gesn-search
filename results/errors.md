# Разбор ошибок

Дообученная e5 (ft) на ручном тесте (138 запросов, разметка v1): правильный код на первом месте у 71 запроса, у 67 — нет. Ниже — откуда берутся промахи. В скобках ранг первой правильной нормы: e5 → ft (— значит нет в top-50).

Данные: [per_query.jsonl](per_query.jsonl) — ранги и top-5 каждого подхода на каждый запрос.

## 1. Бытовое слово ↔ нормативный термин (дообучение помогает частично)

Человек называет вещь, а ГЭСН — технологию или материал.

| Запрос | Как в ГЭСН | e5 → ft |
|---|---|---|
| облицовка стен кафелем | облицовка… керамическими плитками | 46 → 6 |
| перегородка из пеноблока 100 | кладка перегородок из газобетонных блоков | 33 → 14 |
| положить ламинат | покрытие из досок ламинированных замковым способом | 15 → 2 |
| побелка потолка | известковая окраска | — → — |
| лепнина на потолок | установка гипсовых погонных деталей | — → — |
| армопояс по газоблоку | устройство поясов | — → — |
| бетонная подушка под фундамент | устройство бетонной подготовки | — → — |
| декоративная штукатурка короед | мелкозернистые декоративные покрытия | — → 27 |

Синтетика научила модель части синонимов («кафель», «ламинат»), но не тем, которых генератор сам не знал или не употреблял: «побелка», «армопояс», «подушка». Это прямое ограничение генерации без доменного словаря.

## 2. Объект вместо конструкции (не решается)

Запрос называет сооружение, а нормы описывают его элементы: «монолитный погреб», «монолитный септик», «железобетонный бассейн», «залить колодец», «монолитный каркас дома», «собрать бытовку», «построить камин». Все — вне top-50 у обеих моделей. Правильный ответ требует знания, что погреб = монолитные стены подземной части, а септик = ёмкостное сооружение; ни синтетика по нормам, ни сами тексты норм этого не содержат.

## 3. Числа как ложный якорь

Модель цепляется за совпадение числа, а не за смысл:
- «фундамент под колонну 40х40» → облицовка колонн плитами **толщиной до 40 мм** (ft: правильный код на 44 месте);
- «стропила шаг 600» → кронштейны **с шагом 600 мм** для вентфасадов (ft: 4; BM25 здесь — 1);
- «фундаментная плита 400 мм» → гипсовые плиты **400х400** (ft: 31).

Здесь лексический BM25 иногда лучше, но в гибриде с равными весами его шум перевешивает пользу.

## 4. Отраслевые нормы-приманки

В сборнике 06 есть десятки норм для АЭС («армоблоки», «бетонирование особо тяжёлым бетоном по схеме кран-бадья», «фундаментная плита реакторного отделения»). Они лексически близки к бытовым запросам: «армопояс» → «установка армоблоков купола защитной оболочки». Фильтр по типу объекта (жилое/промышленное/АЭС) или исключение узкоотраслевых таблиц из индекса убрал бы этот класс ошибок.

## 5. Правильная таблица, не та строка

Модель находит нужную группу норм, но ошибается в варианте: «гкл в два слоя перегородка 100 мм» → двойной каркас вместо одинарного (ft: 3), «собрать сруб» → сборка стен из брусьев вместо рубки (ft: 9). На уровне таблицы правильный ответ в top-10 у 91% запросов против 77% на уровне кода — разрыв в основном отсюда.

## 6. Регрессии после дообучения

У 13 запросов ft хуже готовой e5, из них заметно: «мягкая кровля» (1 → 16), «стелить рубероид на крышу» (9 → 27), «плита перекрытия 200 мм по профнастилу» (1 → —), «перегородка с шумоизоляцией под гипсокартон» (1 → 5). Это кровельные и составные запросы; вероятная причина — фильтр неоднозначных запросов выбросил ~20% синтетики (короткие общие формулировки вроде «мягкая кровля» встречаются у норм из разных таблиц), и модель видела их меньше всего.

## 7. Ошибки разметки

Просмотр top-5 всех подходов показал, что у 14 запросов в разметке не хватало релевантных норм (например, «Сборка крыльца на 3 ступени» для «крыльцо из ступеней»). Разметка исправлена — см. [LABELING.md](../data/test/LABELING.md); пересчёт метрик на исправленной разметке — следующий шаг.

## Что бы я сделал дальше

1. Генерировать синтетику с доменным словарём синонимов (кафель, армопояс, подушка, побелка…) — закрывает класс 1.
2. Обучать неоднозначные запросы как multi-positive вместо выбрасывания — должно убрать часть регрессий (класс 6).
3. Фильтр отраслевых таблиц (АЭС, градирни, элеваторы) для бытового сценария — класс 4.
4. Класс 2 — не задача ретривера: нужен слой «объект → набор работ» (RAG с LLM или справочник типовых смет).
