# Тестовый набор: как он собран

## Запросы

`queries.txt` — 150 запросов, написанных вручную человеком без сметного опыта, с позиции заказчика. При написании автор видел только названия сборников и разделов (`sections.md`), но не тексты норм. Строки `# NN` — сборник, который автор имел в виду; это только подсказка, правильный ответ может лежать в другом сборнике.

## Разметка

`qrels_spec.txt` → `python -m gesn.qrels` → `qrels.jsonl`.

Разметку делал Claude (LLM) по справочнику норм. Для каждого запроса просматривались кандидаты из top-10 BM25, e5 и гибрида (пулинг), а также весь список из 624 таблиц: так в разметку попадали нормы, которые не нашёл ни один метод. Выборочная проверка человеком не проводилась: автор запросов не сметчик и доверил разметку LLM.

Тест заморожен до дообучения модели. Обучающие данные генерирует другая модель (открытая LLM), так что совпадения стиля теста и обучения нет.

## Правила релевантности

1. Норма релевантна, если смета на эту работу честно может быть составлена по ней одной.
2. Если в запросе нет параметров (материал, толщина, тип), релевантны все подходящие варианты. «Покрасить потолок» — все нормы окраски потолков внутри помещений.
3. Если параметр указан, берутся нормы с этим параметром. Если точного значения в ГЭСН нет («газоблок 300», а нормы есть только на 400 и 500 мм), релевантны ближайшие нормы той же таблицы.
4. Нормы-добавки («на каждые 5 мм изменения толщины добавлять…») сами по себе не считаются ответом. Ответ — основная норма.
5. Если работы нет в 6 выбранных сборниках, запрос остаётся без ответа (12 из 150) и в метриках не участвует. Такие запросы пригодятся позже для проверки порога уверенности.

## Известные ограничения

- Разметку делал один разметчик (LLM) без проверки человеком; спорные случаи есть (например, окраска забора размечена через окраску деревянных поверхностей).
- Пулинг сделан до дообучения: если дообученная модель найдёт релевантную норму вне пула, она будет засчитана как ошибка, пока её не доразметить.
